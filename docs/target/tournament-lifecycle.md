# Жизненный цикл вечернего турнира

**Статус:** Accepted для общего процесса; спорные переходы отмечены как Open

```text
draft -> registration -> running -> finished
   \          \            \
    +----------+-------------+-> canceled
```

## 1. Подготовка

Организатор создаёт турнир, связывает его с сезоном, указывает дату и физический лимит столов. В `draft` параметры можно менять без влияния на участников.

## 2. Регистрация и явка

В `registration` игрок может выразить намерение участвовать. Отдельное действие `mark_arrived` фиксирует фактическую явку. В начальную рассадку входят только пришедшие, а не все зарегистрированные.

## 3. Старт

`start_tournament` атомарно:

1. блокирует конкурирующий старт;
2. снимает snapshot пришедших;
3. рассчитывает число реальных столов;
4. создаёт столы и назначения;
5. переводит турнир в `running`;
6. сохраняет уведомления для последующей доставки.

Повтор команды с тем же idempotency key возвращает прежний результат и не создаёт новые столы.

## 4. Игра

- Пришедший после snapshot обрабатывается сценарием поздней рассадки.
- Выбывание фиксируется один раз и делает участие терминальным.
- При необходимости организатор запускает или подтверждает ребалансировку.
- Закрытие стола меняет доступность стола, но не начисляет очки.

## 5. Завершение

`finish_tournament` допустим, когда порядок всех мест однозначен. Операция атомарно фиксирует последнего оставшегося игрока, строит полный порядок, рассчитывает все `TournamentResult`, переводит турнир в `finished` и ставит публикацию результатов в очередь.

Повторное завершение не должно менять очки. Ручная коррекция опубликованного результата требует отдельного аудируемого сценария.

## Отмена

Отменённый турнир не даёт сезонных очков. Политика отмены уже идущего турнира и восстановления ошибочно отменённого турнира остаётся Open.
